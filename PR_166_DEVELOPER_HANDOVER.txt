Purpose: help a user understand search problems, choose a useful business action,

Application stack: Go API, React/Vite UI, Postgres; existing Google OAuth and SAM.

1. STARTING PROBLEM AND PRODUCT DECISIONS
---------------------------------------
Before: Search Console and GA4 were separate reports. Users had to interpret the
numbers themselves, remember page edits and decide whether a change helped.
After: select a useful outcome, review the top three evidence-backed candidates,
investigate clicks/tracking/index status, prepare a reviewed improvement brief,
save an immutable baseline and compare complete post-change windows.

Do not promise that averages prove a cause, that every key event is a lead, that
all Google UI reports have APIs, or that missing rows mean measured zero.
Avoid automatic paid research, automatic publishing and a dashboard of every
possible metric. Use goal-led defaults with explicit evidence drill-downs.

The original #165 changes are included unchanged in the combined branch:
custom calendar dates and source/device/country/query/page filters; period totals,
trend and country evidence; the content-refresh queue and editor handoff; and
bounded stored-index inspection. Review SearchPerformancePage/Selects/Totals/
Trend/Indexing and backend/internal/gsc/performance.go for that foundation.

2. COMPLETE USER JOURNEY
------------------------
a. Project -> Search Performance -> Search Growth panel.
b. Load my GA4 goals explicitly. Metadata returns registered event-specific
   session rates for this property. Choose an actual successful business outcome.
   Custom registered key events can appear; not just purchase/generate_lead.
c. Optionally set brands, 14/28-day window, previous period vs same weekdays
   364 days earlier, or expanded 5,000-row coverage. Settings do not fetch reports.
d. Click Find opportunities. Default view shows three candidates with evidence
   and one main next action. Other candidates are browsed ten cards at a time.
e. Why clicks are low/falling: explicit two-window, exact-page query evidence,
   low-visibility/position/CTR observations. A separate button inspects only this
   page's stored Google index status. Missing queries remain unknown.
f. Investigation panel: choose a collapsed topic; only one opens at a time.
   Measurement configuration, observed host/referral rows,
   real ordered-event funnel, device rates, submitted sitemap status and saved
   prompt citations. All are explicit reads with independent source limitations.
g. AI brief opens an editable, scoped SAM draft; no model call until Send. The
   search_growth mode retains its read-only tool allowlist and existing metering.
   Selected goal, dates and comparison are carried into the analyst instruction.
h. Editor handoff passes page/query/evidence reference in validated tab storage;
   existing drafts are preserved. Existing selection-based tools remain review/apply.
i. Save an action/note. Optionally choose a similar unchanged comparison page
   from the first 100 other report pages. Server snapshots both baselines.
j. Mark applied only after actually changing the page. The first applied time
   cannot move. Compare after 14/28 complete days plus Google's reporting delay.
k. Optionally enable weekly in-app checks for a selected registered goal.
   Last dated digest shows at most three actions and five meaningful drop alerts.

4. DATA MEANING AND PROVIDER READ BOUNDS
---------------------------------------
- Join GSC final Web pages with Google organic GA4 landing pages. GSC clicks and
  GA4 sessions are different measurements/time zones. No query-level conversion
  attribution. Ambiguous normalized URL variants remain unmatched.
- Raw keyEvents is all configured events. goalRate is the provider's registered
  sessionKeyEventRate:<event>. Never event-filter the full session denominator.
  Sessions x goalRate is only an estimated minimum-success check, clearly labeled.
- Standard analysis: at most 3 GSC + 2 GA4 report reads on cache miss.
  Selected goal adds 1 metadata read. Expanded: at most 15 GSC + 10 GA4 + metadata.
  Ten-minute scoped report cache and per-process singleflight deduplicate requests.
  One report/project; 90-second overall report deadline; dates bounded to 90 days
  with both windows inside GSC history. GSC can omit queries even below row caps.
- Report holds <=10 queries/page. A query holds <=5 example competing URLs plus
  its returned-page count. Do not reintroduce quadratic competing-page output.
- Explicit click investigation: 2 exact-page query reads, <=1,000 rows/window,
  60-second total deadline. Queries absent from a period remain null.
- URL Inspection: separate explicit one-URL read of stored Google state; no live
  test, indexing request or recrawl. Existing general inspector remains <=10 URLs.
- Sitemap status: 1 Google read, 30-second service deadline, 2 MiB response bound,
  first 200 submitted entries. No XML crawling or nested-index expansion.
  Sitemap errors/warnings are counts; detailed reasons stay in Google's report.
  Submitted entries can overlap across content types; do not label them unique
  indexed pages. Preserve the per-type counts.
- Funnel: 1 alpha API read, <=5 distinct tracked event steps, closed ordered user
  sequence, optional device breakdown, <=100 rows, 45-second deadline. Users may
  complete steps across sessions in the selected window. Missing instrumentation
  can resemble abandonment. Sampling/thresholds/restrictions remain visible.
- Attribution check: 1 all-channel host/source/medium report, <=100 rows.
  Self-referral candidates need >=20 sessions. This cannot verify actual tag,
  cross-domain or consent configuration. Direct traffic is not automatically AI.
- Devices: 1 Google-organic report; selected goal adds metadata validation.
- Post-change comparison: 1 exact-page GSC + 1 host/path-filtered GA4 read, plus
  selected-goal metadata when applicable and 1 GSC read for an optional control.
  Control-adjusted click movement needs >=30 baseline clicks on each page and
  >=30 after clicks on the comparison page. Descriptive ratio, not causal proof.

5. DATABASE, SCHEDULING AND MIGRATION REVIEW
-------------------------------------------
Original migration 31: go_search_growth_reports and go_search_growth_actions.
Extension migration 32: go_search_growth_monitors (one row/project), due-time
partial index, scope index and RLS without public-client policies. Trusted server
owner accesses it; no new browser database credentials. Foreign keys cascade on
project/organization deletion. Test fresh migrations and production server role.

Migrations 29/30 in this PR are preparatory copies from PR #163; retain the same
files when merging #163. Do not renumber/delete already-applied migrations.

Weekly checks are OFF until explicitly enabled. Freeze selected property/site
identity and goal. Worker checks current entitlement/connections before reports.
Atomic SKIP LOCKED claim advances the due date before fetching. A revision fence
prevents an old worker from saving into disabled/changed configuration. An
identical enable replay preserves its schedule/revision. Success waits seven days;
failure waits one day. Previous successful digest stays dated. No catch-up loop.

Alert requires both clicks down >=20% from >=30 baseline clicks and selected-goal
rate down >30%, >=100 sessions in each period, and >=5 estimated baseline
sessions reaching that goal. Limited reports suppress alerts. Thresholds identify
investigation candidates, not statistical significance or guaranteed lost sales.

6. MONEY, AUTHORIZATION AND FAILURE BOUNDARIES
---------------------------------------------
No new paid DataForSEO/OpenRouter call is introduced by these reports/drill-downs
or weekly checks. Existing explicit SAM replies retain their credit guard.
No email delivery, automatic site edit, pricing change or production deployment.
Variable names were inspected on Railway; values/keys were not exposed or changed.

Every HTTP route uses session + project access. Repositories include organization
and project, caches include selected connections and analysis inputs. Baselines
come from scoped server reports, not client-submitted metrics. Goal/property/date
changes cannot silently reinterpret an old baseline. Null/limited values are not
filled with zero. Errors never expose provider bodies/tokens. No public indexing
API submissions or server fetch of user-provided sitemap URLs are introduced.

8. HONEST LIMITATIONS / NOT IMPLEMENTED
--------------------------------------
Live Google OAuth/provider reconciliation and a real-account alpha funnel smoke
were NOT performed here; test Google responses were controlled fixtures.
No production migration or deploy was performed. Automated tests do not prove
that a customer's tracking instrumentation or business definitions are correct.

Google's native generative-AI report has an external property/help entry point;
automatic API/CSV ingestion is not implemented. It is not equivalent to all
ChatGPT/Perplexity exposure. BigQuery is an external optional setup link with
Google Cloud cost caveats; no dataset/query billing is enabled automatically.
No arbitrary GA4 metrics/dimensions builder, CRM-qualified leads, complete GSC
Page Indexing UI export, nested sitemap crawler, controlled SEO experiment,
statistical significance claim, automatic competitor/SERP research or weekly email.
Existing crawl/speed/paid SEO tools remain available through their own workflows.
