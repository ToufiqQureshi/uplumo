## What the audit establishes

The concern is valid: the app delivers only part of the documented output of the endpoints it already calls. Some useful fields disappear in Go decoding; others survive the API and Zod but have no UI or export consumer. There are also deliberate limits, conditional fields and operational metadata that must not all be called bugs.

This report traces **official endpoint documentation → actual request options → Go decode/mapping → API/schema → UI/export**. Five parallel audit components cover Keyword Research, Domain Research, Backlinks, AI (including saved tracking), Local SEO, rank checks, content briefs and MCP-only business tools. A `*` in a matrix means the entire subtree, except explicitly retained children. Optional rich variants are grouped rather than falsely described as always-present columns.

**Evidence limit:** this is a documentation/source audit plus focused synthetic regressions. It is not a new captured production raw response compared with every deployed screen. The earlier 138-row live keyword comparison was normalized stored backend data versus UI, not DFS raw versus UI. No paid provider tasks were sent during this audit/recovery.

## Cost and profitability implications

Rendering or exporting fields already present in a response does not require buying that response again. The official [Backlinks pricing](https://dataforseo.com/pricing/backlinks/backlinks) charges by task and returned row; [Labs pricing](https://dataforseo.com/pricing/dataforseo-labs) depends on task/items, with endpoint-specific options. Field count on our screen is not a refund mechanism. Premium clickstream doubles the documented Labs request price. Other endpoints have their own rules; do not apply a Backlinks row formula to all DFS products.

Priorities are: stop repeated purchases; preserve the useful data from each legitimate purchase; expose limits/source/freshness; reconcile actual spend against credits. A visually richer report alone does not establish profitability.

Standard settlement in current code is 1,280 credits per successful provider USD, rounded per operation. Provider-billed failures that refund the customer remain an owner cost; so do ambiguous requests whose bill cannot be inferred from a missing response. Process-local sharing does not prevent duplicate purchases across server instances. Prices, grants and markup were not changed.

One plan-budget mismatch is confirmed under the maximum scheduled Business scenario: 1,000 tracked keywords, weekly, desktop, deepest allowed check, five scheduled runs, 100-keyword queued batches. `5 × 10 × ceil($0.24 × 1280) = 15,400 credits`, above the 15,000 monthly grant. Early target-stop can reduce actual cost but does not guarantee affordability. The existing 4.35-week assertion is not a five-run-month guarantee. This is a product-budget decision, not evidence that all real Business customers currently lose money.

No complete realized-margin sign-off is possible from this audit: actual provider invoices/task spend, recovered credits, grants/discounts/top-ups, failed/refunded work, currency conversion, payment fees/tax and infrastructure must be reconciled over the same window. Older missing provider-attribution records further limit historical claims.

## Recommended implementation order

1. Finish the prepared cost/correctness fixes and real-DB/full-CI verification on a reviewable follow-up to merged PR175.
2. Expose already-retained data first: complete Backlinks profile/history details; Local SEO business details/export; AI evidence export; SERP descriptions. Use expandable details and exports rather than dozens of mandatory columns.
3. Add useful decoder/API fields from the same existing purchases: Domain distributions/value/change, keyword Ads bids and extended metrics, source timestamps, link quality context, content-table evidence. Version normalized caches deliberately.
4. Preserve conditional/source semantics. No zero-for-null substitution, no national metric presented as a local one, no organic/paid ambiguity, no redirect publisher presented as the original publisher. Mark truncation and sample sizes.
5. Complete endpoint-specific captured-response fixtures through mapper/schema/render/export. Then compare an authorized deployed raw sample, screen/export, provider task count and credit ledger for the exact same request.

### Intentional reductions and downstream loss

- `labsRows` normalizes and deduplicates terms; `interleave` enforces the result limit. Case variants and additional rows beyond limits cannot all appear independently.
- Optional frontend grouping hides repeated volume/CPC/competition/bid/link/growth cells on child rows; it does not remove their values from the underlying research result/export. This is a display choice, not provider omission.
- Local blending replaces volume/CPC/competition/monthly history with the local Ads result while retaining national difficulty/intent/link context. These sources should be explained, not implied to all be local measurements.
- Saved metric persistence and refresh use a smaller `metricRow` contract: volume/CPC/competition/difficulty/intent/monthly history. Saving does not preserve the extra research bid, backlink and growth fields. The original provider response is not archived here.
- Research snapshots are normalized caches. Previously discarded fields cannot be recovered from old snapshots by a frontend-only change; decoder/API additions need cache-version handling and can make the next explicit lookup a new paid purchase.

### Operational envelope versus customer data

Shared task envelope version/status/message/time/cost/count/id/path/request echoes are handled by the shared client for execution/errors/metering. These do not all belong in customer table columns. Auditing spend must inspect task/ledger records separately; hiding provider cost from a customer report is not the same as failing to record it.

### Priorities

1. Complete zero-extra-call delivery: Ads bids, monthly/yearly growth, secondary intent, category/language/core-term context, backlink benchmarks, provider update times; show them in expandable details/export instead of forcing dozens of columns.
2. When premium clickstream is selected, expose the purchased demographics and alternative volumes with their source labels, or explicitly narrow the product promise. Do not silently enable premium options for everyone.
3. Preserve actual live SERP descriptions, rich organic details and returned feature types; do not invent Labs metrics on the live endpoint.
4. Make truncation, sample limits and saved-versus-research differences explicit. Consider a safe normalized detail export; it should retain customer data without secrets/unsafe links or new paid requests.

#### Variant and operational boundaries

- SERP rich content is type-specific. Organic/paid/local/snippet/AI-reference variants cannot be flattened into a promise that every row has every rating, sitelink, address or reference field. Current decoder omits the complete variant-specific subtree apart from the explicit rank/traffic/URL exceptions above.
- Task ID/status/cost/path/body echoes are operational. Shared transport handles status and task-reported spend. They do not need a customer table column merely to claim raw equality.
- `FetchedAt` is generated by Uplumo when retrieved. It does not preserve the provider's dataset update timestamp.
- Cached responses are normalized objects, so dropped raw data cannot later be recovered from this cache without another purchase. A field-delivery fix needs a cache-version change.
- Keyword/page CSV and Sheets currently mirror the seven/three displayed columns. Raw data discarded upstream cannot be recovered by JSON/records export. Selected-keyword saving retains only keyword and volume/CPC/difficulty; it is a separate save contract.
- Domain overview never purchases Backlinks summary. Its compatibility `backlinks`/`referringDomains` API properties are explicitly null, and the UI renders only the two organic tiles. A missing domain-wide backlink count must not be 'fixed' by silently adding a paid endpoint.

### Common technical fields: do not call all of these missing customer metrics

All five endpoints share `version`, `status_code`, `status_message`, `time`, `cost`, `tasks_count`, `tasks_error`, `tasks[].id/status_code/status_message/time/cost/result_count/path/data/result`. List envelopes use `target`, `items_count`, `items`, `total_count`, plus individual item `type`. `total_count` drives pagination; array length substitutes for item count and requested inputs substitute for target/mode. Individual `type` discriminator is omitted. Row endpoint also echoes `mode`/`custom_mode` and offers `search_after_token`; token is discarded. History `date_from`/`date_to` are not copied to the response; the request already defines its date window.

1. Finish existing summary delivery: show crawled pages, types and attributes, preserve unknown bucket, and make all received breakdown entries accessible. Correct nofollow and rank descriptions.

3. Preserve and expose useful page/domain aggregate dates, spam, nofollow, IP/subnet, page counts and breakdown maps. No extra endpoint is required for those fields when the current provider response supplies them.
4. Make existing history rank and new/lost referring-domain series accessible, with monthly cadence and scope explicitly labelled.
5. Decide separately whether additional provider dataset coverage is needed (`all`/`lost`, more than the default internal breakdown limit, >20,000-row token traversal). These alter retrieval scope; they must not be silently bundled with a display fix or billed as though already purchased.

### Provider boundaries and remaining unknowns

- Site Audit: `audit/lighthouse.go` calls `pagespeedonline.googleapis.com/pagespeedonline/v5/runPagespeed`; `NewPageSpeedProvider` wired in server main. It shares Google's quota, not DFS spend. Existing `dataforseo-lighthouse` labels are compatibility for historical payloads.
- Ahrefs domain rating uses `api.ahrefs.com/v3/public/domain-rating-free`, not DFS.
- OpenRouter generation/token output is not DFS. Google Search Console/GA4/CrUX are separate providers.
- Endpoint envelopes (status/cost/task IDs/path/request echo) belong in metering, diagnostics and provenance. Their omission from the main customer grid is not automatically a lost SEO insight.
- No live provider API calls, no production DB queries and no paid captures were performed in this audit. Actual nullability/presence by query must be verified against owner-approved captured raw samples, with secrets removed.
- No numeric “percentage of DFS data shown” is defensible: conditional fields, nested entities, summary limits and task metadata make field counts misleading.
- Local Finder's complete documented item/result families are mapped above. Every rich organic SERP subtype was not individually enumerated here. The decoder-level conclusion is precise: any unlisted field is discarded by that decoder or UI allowlist; this does not assert every field occurs on every response.
- Changes needed beyond the hours bug are identified findings, not implemented features. Full raw-to-browser automation and post-deploy capture comparison remain outstanding.
